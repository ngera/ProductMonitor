Hierarchy: Product → Area → Feature. Every area must have at least one feature. A feature's description is the prompt the LLM uses to recognise content about it — write it the way you'd brief a person doing the labelling manually.

What goes in each field?

Area id: kebab-case, stored in the DB and reports. Used in URLs and as a group key. Stable — renames mean trend discontinuity.

Area display: human-readable label shown in reports and the LLM prompt.

Area keywords: comma-separated. Used by the regex filter and as hints in the classifier prompt. Doesn't have to be exhaustive — the LLM does the heavy lifting.

Entity type hint: comma-separated entity types (gpu, cpu, audio_device, network_adapter, …) that this area should "own" when an entity of that type is implicated. First-declared area wins on conflict.

Feature id: kebab-case, unique within the area. Used as a stable key.

Feature display: human-readable label shown in reports.

Feature description: this is the prompt. Write what content about this feature looks like — symptoms, technologies involved, common keywords, what NOT to count. The LLM reads it during classification. Aim for 2-4 sentences. Concrete > abstract. Examples of language users use are gold.
